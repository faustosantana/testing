# 05 — THE TRANSFORMATION

## Antes

El SGB existe, pero requiere adaptacion para nube moderna, personalizacion institucional y modulos adicionales. La informacion puede estar limitada por procesos, interfaces o capacidades que no cubren completamente la operacion futura de INCABIDE.

## Despues

El SGB se convierte en una plataforma:

- desplegada en Azure;
- accesible por dominio institucional;
- con TLS activo;
- con modulos originales operables;
- con API funcional;
- con evidencias de seguridad;
- con documentacion tecnica;
- con capacitacion;
- con soporte;
- preparada para evolucion modular.

## Cambio institucional

| Dimension | Antes | Despues |
| --- | --- | --- |
| Visibilidad | Informacion menos centralizada. | Dashboard ejecutivo y reportes. |
| Trazabilidad | Dificil reconstruccion completa. | Timeline, auditoria y cadena de custodia. |
| Seguridad | Requiere reforzamiento. | MFA, RBAC, cifrado, WAF, vault y monitoreo. |
| Operacion | No cloud-ready. | Plataforma desplegada en Azure. |
| Documentacion | Requiere consolidacion. | Manuales, runbooks y evidencias. |
| Evolucion | Modulos faltantes. | Desarrollo modular por prioridad. |

## Cambio para usuarios

- Direccion gana visibilidad.
- Operadores ganan guias y validaciones.
- Auditores ganan evidencia.
- TI gana procedimientos.
- PADF/INCABIDE ganan control de aceptacion.

## Transformacion esperada

La transformacion no se mide solo por tecnologia, sino por la capacidad de convertir eventos operativos en informacion confiable para decision, cumplimiento y rendicion de cuentas.
