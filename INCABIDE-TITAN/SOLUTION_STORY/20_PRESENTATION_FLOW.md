# 20 — PRESENTATION FLOW

## Proposito

Flujo narrativo para una presentacion futura. No se generan diapositivas en esta fase.

## Flujo sugerido

| Seccion | Mensaje | Objetivo |
| --- | --- | --- |
| 1. Apertura | INCABIDE necesita una plataforma confiable para bienes sensibles. | Enmarcar problema. |
| 2. Contexto RFP | El SGB existe, pero requiere adaptacion cloud, seguridad y modulos. | Mostrar comprension. |
| 3. Ciclo de vida del bien | Desde ingreso hasta disposicion final. | Hacer visible el proyecto funcionando. |
| 4. Vision de solucion | Plataforma segura, trazable y operable. | Presentar direccion tecnica. |
| 5. Experiencia ejecutiva | Dashboard de decision en 30 segundos. | Conectar con direccion. |
| 6. Experiencia operativa | Registro, custodia, documentos, aprobaciones. | Conectar con usuarios. |
| 7. Seguridad y auditoria | MFA, RBAC, cifrado, logs, evidencias. | Responder riesgo critico. |
| 8. Azure y operacion | Nube, monitoreo, backups, soporte. | Mostrar sostenibilidad. |
| 9. Etapa I | Adaptacion, despliegue, documentacion, capacitacion. | Alinear con RFP. |
| 10. Etapa II | Modulos priorizables y aceptacion parcial. | Mostrar evolucion controlada. |
| 11. Resultados esperados | Visibilidad, trazabilidad, seguridad, decision. | Cerrar valor. |
| 12. Mensaje final | Cada bien, una historia trazable; cada decision, una evidencia. | Cierre ejecutivo. |

## Reglas de presentacion

- No abrir con tecnologia; abrir con el ciclo de vida del bien.
- No exagerar beneficios.
- Citar conceptos de la RFP sin sobrecargar.
- Mostrar seguridad como control de confianza.
- Mostrar Azure como plataforma obligatoria y gobernable.
- Separar API base de PGR opcional.
- Conectar cada modulo con una decision institucional.

## Mensaje final recomendado

Justech propone una solucion que entiende el proyecto como gobierno digital: tecnologia, seguridad, evidencia, operacion y transferencia para que INCABIDE administre cada bien con trazabilidad desde su ingreso hasta su disposicion final.
