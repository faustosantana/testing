# 16 — RISK MANAGEMENT

## Objetivo

Presentar el enfoque de gestion de riesgos tecnicos, funcionales, de seguridad y operativos.

## Riesgos principales

| Riesgo | Gestion propuesta |
| --- | --- |
| Codigo fuente no disponible antes de adjudicacion | Diagnostico inicial y supuestos controlados. |
| API sin alcance minimo definido | Preguntas PADF y separacion de API base/PGR. |
| Azure sin region/dimensionamiento | Matriz de decisiones y supuestos de costo. |
| Seguridad con penalidades severas | DevSecOps, evidencias y pentest. |
| Soporte critico ambiguo | Aclaracion y modelo de escalamiento. |
| Subastas con alcance ambiguo | Validar sistema existente e integracion. |
| Datos/migracion no definidos | Estrategia condicionada y levantamiento. |

## Relacion con la RFP

La RFP incluye penalidades por atraso, calidad insuficiente, seguridad, abandono, subcontratacion no autorizada y confidencialidad/PI.

## Requisitos cubiertos

- PEN-001 a PEN-021.
- SEC-001 a SEC-038.
- QA-001 a QA-029.
- AZ-001 a AZ-015.

## Evidencias necesarias

- Registro de riesgos.
- Planes de mitigacion.
- Decisiones pendientes.
- Evidencias de QA y seguridad.

## Dependencias

- Respuestas PADF.
- Confirmacion de alcance.
- Equipo y capacidades Justech.

## Pendientes de informacion de Justech

- Matriz interna de riesgos.
- Politicas de continuidad.
- Procedimientos de seguridad.
- Cobertura de seguros/garantias si aplica.
