# 01 — DESIGN PHILOSOPHY

## Vision

El SGB de INCABIDE debe sentirse como una plataforma SaaS institucional moderna: sobria, rapida, segura, clara y orientada a decisiones. La experiencia no debe parecer un sistema gubernamental heredado, sino una consola profesional comparable a Azure Portal, GitHub Enterprise, Stripe Dashboard, Atlassian y Linear.

## Principios de experiencia

| Principio | Aplicacion |
| --- | --- |
| Claridad ejecutiva | Lo importante debe entenderse en menos de 30 segundos. |
| Trabajo guiado | Cada flujo debe indicar proximo paso, responsable y estado. |
| Confianza | Auditoria, permisos, evidencia y cambios visibles. |
| Reduccion cognitiva | Menos campos visibles, mas progresive disclosure. |
| Accion contextual | Botones y alertas donde el usuario decide. |
| Consistencia | Patrones repetibles en todos los modulos. |
| Institucional premium | Sobriedad visual, no saturacion, tono profesional. |
| Seguridad visible | Permisos, confidencialidad y trazabilidad comprensibles. |

## Tono de producto

- Profesional sin ser frio.
- Moderno sin ser decorativo.
- Institucional sin ser burocratico.
- Potente sin ser complejo.
- Seguro sin intimidar al usuario.

## Experiencia objetivo

El usuario debe sentir que el SGB:

1. le muestra prioridades;
2. reduce errores;
3. evita perdida de informacion;
4. facilita auditoria;
5. acelera busqueda;
6. permite decidir con datos;
7. protege informacion sensible.

## Anti-patrones prohibidos

- pantallas saturadas de campos;
- tablas sin filtros potentes;
- formularios sin guardado parcial;
- botones genericos sin contexto;
- errores tecnicos incomprensibles;
- navegacion profunda sin breadcrumbs;
- reportes visualmente densos;
- permisos invisibles para el usuario;
- estados vacios sin orientacion.

## Criterio de exito UX

Un Director debe entender la situacion institucional en 30 segundos. Un operador debe registrar un bien sin entrenamiento excesivo. Un auditor debe reconstruir una decision sin pedir explicaciones fuera del sistema.
