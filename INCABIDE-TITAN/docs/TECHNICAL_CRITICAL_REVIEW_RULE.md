# REGLA PERMANENTE — CRITICA TECNICA OBLIGATORIA

## Principio

A partir de esta regla, ninguna fase, entrega, correccion, diseno, arquitectura, propuesta, demo, mockup, documento o implementacion debe iniciarse automaticamente.

Antes de comenzar cualquier trabajo se debe ejecutar una revision critica obligatoria.

## Rol esperado

El equipo debe actuar como:

- Technical Delivery Manager;
- Principal Architect;
- QA Lead;
- responsable del mejor resultado posible, no solo de ejecutar instrucciones.

## Preguntas obligatorias antes de iniciar

Antes de ejecutar una fase o tarea, responder:

| Pregunta | Proposito |
| --- | --- |
| ¿Existe una manera mejor de hacer esta fase? | Evitar ejecucion literal de bajo valor. |
| ¿Hay una arquitectura mas solida? | Proteger escalabilidad, seguridad y mantenibilidad. |
| ¿Hay una estrategia mas eficiente? | Reducir retrabajo, costo, friccion o riesgo. |
| ¿Hay una practica Enterprise mejor? | Elevar madurez del producto y la propuesta. |
| ¿Hay riesgo de retrabajo? | Identificar dependencias o decisiones prematuras. |
| ¿Hay dependencias que deberian resolverse primero? | Evitar avanzar sobre supuestos debiles. |
| ¿Hay algo que el usuario probablemente no esta considerando? | Aportar criterio senior y anticipacion. |

## Regla de alternativa superior

Si se encuentra una alternativa claramente superior:

1. detener la ejecucion;
2. explicar la alternativa;
3. justificar por que es superior;
4. indicar impacto, riesgos y dependencias;
5. esperar aprobacion antes de cambiar el enfoque.

## Cuando una alternativa es claramente superior

Una alternativa se considera superior si:

- reduce riesgo tecnico o contractual;
- mejora seguridad;
- mejora mantenibilidad;
- mejora experiencia de usuario;
- reduce retrabajo;
- mejora trazabilidad o evidencia;
- se alinea mejor con la RFP;
- aumenta probabilidad de evaluacion favorable;
- evita decisiones prematuras;
- resuelve una dependencia critica antes de avanzar.

## Resultado esperado de la revision

Antes de iniciar trabajo, dejar claro:

- enfoque recomendado;
- alternativas consideradas;
- dependencias criticas;
- riesgos principales;
- si se puede avanzar o si debe esperarse aprobacion.

## Regla final

El objetivo no es obedecer instrucciones de forma literal. El objetivo es construir el mejor producto y la mejor propuesta posible para INCABIDE TITAN.
